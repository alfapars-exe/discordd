# Frozen synthetic key backup fixtures

These files contain patterned test bytes and a public test password. They are not user archives or usable device identities. Keep the ciphertext fixed; do not regenerate it as part of ordinary tests.

Both were generated by running `createBackup` from commit `f33f6d9a4afbd1591d04542f77858b3de53d85a1` against a mocked storage reader, before the storage/codec extraction. The current implementation was restored immediately afterward. No real key database was read or written. Salt and nonce were generated by that writer and are now frozen with the ciphertext.

| File | Historical writer adaptation | SHA-256 of UTF-8 file with LF line endings |
|---|---|---|
| `key-backup-v1-current.json` | No logic changes; original 2,000,000-iteration algorithm identifier retained. | `75a4b24a24cb08aa4ae64e7fb85a87b2f1fbbd831d807023901946d480f9f961` |
| `key-backup-v1-legacy.json` | The writer's default iteration constant was set to 1,000,000 and the external algorithm field omitted to emulate the documented pre-audit envelope. This is an emulation, not an archived output of a pre-audit release. | `d8fca4538cbd78c67623c4cb49177f2609f71196e2011def19ecae1877f4c52e` |

The reader fixture included identity/signing keys, registration, signed and one-time prekeys, a complete ratchet session with a skipped key, sender-key anchor and replay window, a trusted identity, a cached message, and `nextPrekeyId`. Expected byte values are asserted explicitly in `keyBackup.fixedFixtures.test.ts`. The test also freezes provenance/file hashes and rejects wrong passwords, truncated ciphertext, and another authenticated owner before target clearing.

This proves compatibility for these recorded vectors. It does not prove compatibility with every historical user archive, physical device recovery, or correctness of the patterned keys for live messaging.
